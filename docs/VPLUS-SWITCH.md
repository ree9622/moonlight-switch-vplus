# Moonlight V+ Switch 0.1.1

스위치 홈브루용 시험판입니다. Moonlight-Switch를 바탕으로 Moonlight V+의
Foundation Sunshine 확장 기능을 옮겼습니다. 안드로이드판의 전체 기능을 제공하지 않습니다.

## 설치

1. 배포 파일의 `switch/Moonlight-Switch-VPlus` 폴더를 SD 카드의 `switch` 폴더에 복사합니다.
2. 기존 Moonlight 폴더와 설정을 덮어쓰지 마세요. 이 앱의 설정은
   `sdmc:/switch/Moonlight-Switch-VPlus`에 별도로 저장됩니다.
3. 홈브루 메뉴를 전체 메모리를 쓸 수 있는 타이틀 전환 방식으로 열고
   **Moonlight V+ Switch**를 실행합니다.
4. 컴퓨터를 추가하고 연결 승인 번호를 컴퓨터에서 입력합니다.
5. 첫 연결은 1280×720, 초당 60장, H.264, 10 Mbps, HDR 끄기로 시험합니다.

기본 스트리밍은 일반 Sunshine 및 Vibepollo와도 사용할 수 있습니다. 방송 중 화질 조절은
호환되는 `/bitrate` 확장 기능을 사용하는 송출 프로그램이 필요합니다. Vibepollo 소스에서도
이 기능을 확인했으며, 실제 설치된 버전과 스위치의 연동은 별도로 검증해야 합니다.
단축 명령은 Foundation Sunshine의 `SuperCmds` 확장 기능이 필요합니다. 기존 컴퓨터의 서버를
이 시험판 설치를 위해 자동으로 교체하거나 재시작하지 않습니다.

## 추가 기능

스트리밍 중 `-`와 `+`를 함께 눌러 메뉴를 연 뒤 **추가 기능** 탭을 선택합니다.

- **방송 중 화질 조절**: 3~60 Mbps 중에서 고릅니다. 컴퓨터가 변경을 확인한
  경우에만 실제 적용값을 표시하고 다음 연결의 설정으로 저장합니다. 컴퓨터가 전송률을
  제한하면 요청값보다 낮아질 수 있습니다. 영상 크기나 초당 장수는 바뀌지 않습니다.
- **컴퓨터 단축 명령**: 현재 앱에 대해 컴퓨터가 제공한 명령만 표시합니다.
  실행 여부를 한 번 더 확인하고 보냅니다. ‘접수’는 컴퓨터가 요청을 수락했다는 뜻이며,
  명령 자체의 완료를 뜻하지 않습니다.
- **명령 목록 새로고침**: 컴퓨터에서 해당 앱의 명령 설정을 변경한 뒤 사용합니다.

요청 제한 시간은 15초이고 자동으로 재시도하지 않습니다. 오류 또는 제한 시간 초과 시
컴퓨터에서 결과를 확인한 뒤 다시 조작하세요.

## 아직 제공하지 않는 기능

원격 화면 선택, 마이크 전달, 프레임 생성, 내장 가상망, 안드로이드 터치 배치 편집은
이 버전에 포함되지 않습니다. 스위치에서 영상·소리·조이콘과 두 추가 기능이 실제로
작동하는지 확인한 뒤 후속 범위를 정합니다. 본체의 펌웨어·부트로더·오버클록 설정은 바꾸지 않습니다.

## 검증 범위

자동 검사는 잘못된 응답을 성공으로 오인하는 경우, 다른 앱의 명령 혼입,
문자 인코딩과 요청 매개변수 구분을 검사합니다. 빌드 성공과 실제 스위치 실행 결과는 구분합니다.
실기기 검증 전에는 원본 앱을 삭제하지 마세요.

## 0.1.1 입력 수정과 성능 확인

접속마다 컨트롤러 등록을 새로 하고, 등록한 뒤 버튼·스틱·모션을 전송합니다.
재접속 전에 등록했던 상태는 버리며, 메뉴를 열고 닫을 때 눌린 키와 터치 상태를 해제합니다.
등록한 터치 포인터만 이동·해제·취소할 수 있습니다. 빈 터치 상태를 계속 취소하는 동작을 제거했습니다.

스위치 빌드는 NVTEGRA 영상 처리 장치와 deko3d 표시 경로를 사용합니다. 장치 초기화가
실패하면 연결이 실패하며, 이 경로에서 조용히 소프트웨어 디코딩으로 전환하지 않습니다.
다만 소스 경로와 개별 기기에서 성공한 프레임 처리는 서로 다른 근거입니다.

재생 중 `-`와 `+`를 함께 누르고 **옵션 → 디버그 정보**를 켜면 다음을 볼 수 있습니다.

- 첫 줄: 시험판 버전·소스 커밋·영상 형식·실제 프레임 형식·하드웨어 여부
- 왕복 지연과 변동, 수신·디코드·표시 속도, 디코딩 시간과 대기 시간, 프레임 손실
- 영상 큐의 현재 크기·대기 목표·최대 크기

첫 프레임 이전에는 처리 방식이 `pending`으로 표시됩니다. 실제 프레임 형식이
`nvtegra`이고 `hardware`로 표시되는지를 확인합니다. 숫자만으로 체감 지연이 완전히
측정되는 것은 아닙니다. 통계 표시는 기본으로 꺼져 있고, 계산은 초당 네 번으로 제한합니다.

별도 `performance.log` 파일에는 약 5초 간격으로 버전·소스·화면 조건과 위 수치를 기록합니다.
전체 HTTP 로그를 저장하지 않으며 주소·인증서·키·연결 승인 정보는 기록하지 않습니다.
파일은 512킬로바이트까지 기록하며, 렌더링 스레드에서 SD카드에 쓰지 않습니다.
이전 버전의 `log.log`와 혼동하지 마세요.

기존 1.5.0과 비교할 때에는 같은 장소·같은 호스트·같은 화면을 쓰고,
양쪽을 1280×720·초당 60장·HEVC 8비트·SDR·10 Mbps로 맞춥니다.
첫 연결의 기본값은 H.264이므로 비교할 때에는 명시적으로 HEVC를 선택합니다.
양쪽에서 통계 표시 여부도 같게 합니다. 설정 파일의 프레임 큐 크기도 함께 기록합니다.
기본 큐 크기 3인 현재 표시 경로는 최대 2프레임의 지터 여유를 목표로 하므로,
60장 기준 약 33밀리초의 버퍼 대기가 생길 수 있습니다. 이는 실제 체감 지연 측정값이 아닙니다.
0.1.0에서 이 코드가 이미 쓰였으며, 0.1.1에서는 실제 큐 크기를 함께 기록합니다.

호스트에서 세션당 한 번 기록되는 `0x0000000D`는 공통 라이브러리의 구형 진동 활성화
알림과 일치합니다. 5세대 컨트롤러 상태 패킷은 다른 식별자를 쓰므로, 이 신호 하나를
컨트롤러 등록 실패와 같은 문제로 취급하지 않습니다.

**추가 기능 → 영상 버퍼**에서 기존 값을 유지하거나 1·2·3을 고를 수 있습니다.
선택한 값은 다음 연결에 적용되므로, 저장 후 연결을 끊고 다시 접속합니다.
먼저 기존 값으로 동일 조건 비교를 하고, 이후 1을 골라 지연과 끊김의 변화를 별도로 확인합니다.
1은 지터 여유를 최소화하므로 와이파이가 흔들리면 끊김이 늘 수 있습니다.
앱은 기존 설정값을 자동으로 바꾸지 않습니다.

모션 센서는 컴퓨터가 해당 컨트롤러의 모션 보고를 요청한 경우에만, 요청한 속도로 전달합니다.
일반 Xbox 방식에서는 불필요한 센서 패킷을 계속 보내지 않으며, 모션을 지원하는 호스트가
요청하면 다시 사용할 수 있습니다. 진동 지원을 전역으로 끄는 수정은 하지 않았습니다.
